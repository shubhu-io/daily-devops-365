# Content Repurposing & Multi-Platform Syndication Matrix

> **Golden Rule**: Never copy-paste raw text across platforms. Every platform has distinct native mechanics, reading speeds, and user intents. Repurpose the **core technical insight**, not the identical formatting.

---

## 1. The 1-to-6 Content Multiplier Engine

One core technical breakthrough (e.g., *"Debugging Kubernetes CrashLoopBackOff: Exit Code 137 vs 143"*) fuels an entire week of cross-platform visibility:

```
                  [ 1 Core Engineering Event / Build ]
                                    │
       ┌────────────────────────────┼────────────────────────────┐
       ▼                            ▼                            ▼
[ LinkedIn ]                   [ X / Twitter ]               [ GitHub ]
In-depth breakdown post         6-tweet technical teardown    Markdown commit in
+ 8-slide PDF carousel          + terminal screenshot         /troubleshooting-docs
       │                            │                            │
       ▼                            ▼                            ▼
[ Instagram / Threads ]       [ Dev.to / Medium ]         [ YouTube Shorts ]
Dark-mode carousel graphic    Comprehensive, search-ready   60-second video:
+ conversational observation  technical tutorial guide     "Why K8s kills Pods"
```

## 2. Platform Adaptation Matrix

| Platform | Audience Mindset | Optimal Format | Adaptation Rule |
|---|---|---|---|
| **LinkedIn** | Professional, career-focused, seeks clear architecture and engineering standards | 1,200–2,000 character post with short paragraphs + ASCII/Infographic OR 8-10 slide PDF | Focus on **business value**, **reliability**, **architecture**, and **engineering lessons**. |
| **X (Twitter)** | Fast-paced, developer-heavy, values concise hot-takes, code snippets, and direct dialogue | Thread (4–7 tweets) or single high-density tweet with terminal screenshot | Cut the pleasantries. Lead directly with the bug/command. End with a link to the GitHub commit or LinkedIn carousel. |
| **GitHub** | Code-first, audit-minded, looking for runnable proofs | Clean markdown file with runnable commands, configs, and architecture diagrams | Strip the social hook. Provide strict technical documentation: Problem, Root Cause, Remediation, Architecture. |
| **Instagram** | Highly visual, mobile-first, appreciates aesthetic design | Dark-mode carousel (1080x1350 vertical format) | Maximize visual contrast. Use large fonts, monospaced code blocks, and clear visual hierarchy. Minimal caption with full cheat sheet. |
| **Threads** | Casual, conversational, real-time developer stream | 1–3 short paragraphs or single punchy observation | Express honest learning moments: *"Spent 40 minutes debugging a CI failure only to realize I had a trailing space in my YAML secret. What's your most humbling syntax error?"* |
| **Dev.to / Hashnode** | Search engine discovery, long-tail technical readers | Full 800–1,500 word markdown technical article | Consolidate 3–4 related daily posts into a complete, indexed guide. Link back to your GitHub repository and LinkedIn profile. |
